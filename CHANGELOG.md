# agentlore

## 0.1.0

### Minor Changes

- cc03446: Index Cursor chats (experimental) and Gemini Antigravity brain artifacts. Cursor conversations are read incrementally and read-only from Cursor's `state.vscdb` (macOS, Linux and Windows paths, `AGENTLORE_CURSOR_DIR` to override), with each chat mapped to the folder of the window it was started in. Antigravity's markdown artifacts (task lists, plans, walkthroughs) are indexed as notes (`AGENTLORE_ANTIGRAVITY_DIR` to override); its encrypted conversations are not read. The MCP `search` tool now names the supported tools and asks agents to search before grepping other repos.
- cc03446: First release: index Claude Code and Codex sessions; cross-project search via CLI and MCP.
- cc03446: Add knowledge mode. `lore mode on|off [--here]` (and `lore mode reset --here`) turns it on globally or per folder, stored in `~/.agentlore/mode.json`. When it is on, the MCP server tells agents in every client to search past sessions at the start of each new task instead of only when earlier work matters. For Claude Code, `lore hooks install claude` adds a `UserPromptSubmit` hook (the settings file is backed up first; `lore hooks uninstall claude` and `lore hooks status` are also available). In knowledge mode the hook adds pointers to clearly related excerpts from other projects (the best one as a short passage, at most 900 characters in all) and asks the agent to call the `context` or `search` tool before answering; generic prompts get nothing. It never blocks a prompt. `lore` now loads the MCP SDK only for `lore mcp`, so the other commands start faster.

### Patch Changes

- cc03446: New source: Claude Code's prompt history (`~/.claude/history.jsonl`, tool `claude-history`). For sessions whose transcript Claude Code already deleted, the prompts you typed are indexed, with pasted text put back from `~/.claude/paste-cache`, so your own words and decisions from those sessions are searchable again.
- cc03446: Decision and correction words can be extended in `~/.agentlore/words.json` (`decisionWords`, `correctionWords`), read on every search. The built-in lists gained everyday Vietnamese ("duyệt", "làm luôn", "đồng ý", "lộn", "ý tôi là", …) and English ("go ahead with", "I meant", …) phrases.
- cc03446: New `lore schedule install|status|uninstall`: runs `lore index` once a day with the OS scheduler (launchd on macOS, a systemd user timer on Linux, Task Scheduler on Windows), so new sessions are indexed and deleted ones kept even on days nothing searches. `--at <HH:MM>` sets the time and `--dry-run` shows what would be written.
- cc03446: Search hits now say `user decided` for a user turn that decides something, and `--said decision` (MCP `said: "decision"`) keeps only those. A cited file is checked on disk (`file gone now`, `line gone now`, `file changed since`). A hit that a later hit seems to correct ranks lower and says `corrected later? see <id>`. Chunks that mostly repeat a better hit, such as a prompt pasted into a subagent, are left out.
- cc03446: Redaction now covers a `user/password` or `user:password` pair right after an IPv4 address (`203.0.113.7 root/ secret`, also on the next line), and no longer takes an IP address quoted after a password word for the password. Existing indexes are rebuilt once.
- cc03446: Sessions whose transcript is deleted (Claude Code deletes transcripts inactive for 30 days by default) now stay searchable: agentlore archives what it indexed from them, keeps it across rebuilds and redacts it again when the rules change. `lore forget <id>` removes such a session, and `lore status` shows how many are kept. Existing indexes are rebuilt once.
- cc03446: Knowledge mode: pick a prompt's key terms outside the current session and project, so a prompt asked before in the same folder no longer silences the hook; match adjacent Vietnamese syllables as one phrase ("đảo ngược" no longer matches "lừa đảo"); stop filler words from using up the term cap; treat generic Vietnamese coding words as filler.
- cc03446: Knowledge mode no longer adds context to chatty prompts that share a single rare word with a past
  session: at least 2 key terms must each be rare (in at most 5% of the index). The added note
  now tells the agent that excerpts are what past sessions said, to be checked against the code.
- cc03446: Project memory (docs/adr/0004): sessions save what they learned about a project as Markdown notes (`~/.agentlore/memory`, a brief plus topics, old versions kept) with the new MCP `remember` tool and read them with `recall`; notes are indexed and rank above transcripts. Where knowledge mode is on, Claude Code sessions start with the project's brief, topics and related projects (`SessionStart` hook), and a `Stop` hook now and then asks the agent to save what it learned; run `lore hooks install claude` again to add them. The prompt hook now includes the current project's other sessions. `lore consolidate` (opt-in, uses your Claude quota) updates notes from new sessions with `claude -p`, also daily with `lore schedule install --consolidate`. New commands: `lore memory`, `lore group`, `lore consolidate`.
  
  Knowledge spreads between sessions faster: the `Stop` hook asks the agent to save a decision as soon as the user makes one (a turn with a decision word), not only after ~250 KB of transcript; open sessions are told at their next prompt which project notes changed; and a new `SessionEnd` hook indexes an ended session in the background. Run `lore hooks install claude` again to add it.
  
  A user profile (`~/.agentlore/memory/_user/profile.md`) says how the user works and talks, for every project: sessions start with it, `recall`/`remember` read and save it with topic `user`, the `Stop` hook asks agents to save the user's corrections to it, and `lore consolidate` updates it from the user's own messages. `lore memory save` saves a note or the profile from the shell, for sessions whose MCP server predates `remember`.
- cc03446: Search hits now say who said their matching part (`user said`, `agent cites <file:line>`, `agent cites <file:line> + unverified claims`, `agent claim, unverified`, `agent task`; a citation only covers the sentence it is in), and rank an agent's unverified conclusions and agent-to-agent tasks below the user's words and answers that cite a file. Redaction now also covers passwords written in prose next to a login or password word (``login `user / secret` ``, ``password (`secret`)``, in English and Vietnamese) and later mentions of a secret in the same message; existing indexes are rebuilt once.
- cc03446: Hardening from a code review:
  
  - Redact passwords in `curl -u user:pass`, `redis-cli -a pass` and `Authorization: token …`, and in password values that look like a one-folder path. Existing indexes are rebuilt once so the new rules apply to old content.
  - Search and the prompt hook leave out the current project and session inside the query, so a project with many matching chunks no longer hides matches from other projects.
  - Indexing is safe when two processes index the same source: the lock is never taken from a live process, a holder that lost the lock stops, and a save made from an outdated checkpoint is refused instead of duplicating chunks. An older agentlore no longer rebuilds an index written by a newer one.
  - Lines over 64 MiB are skipped instead of failing the file on every run.
  - `lore mode on|off|reset` refuses to overwrite an invalid `mode.json` (it used to drop every saved rule); `lore hooks status` reports an invalid `settings.json` instead of "not installed"; `lore search -n` accepts at most 100.
  - Excerpts neutralise markup-like tags; the Windows hook command escapes `$` and backticks; a refused settings write no longer rotates out older backups; an existing `AGENTLORE_HOME` keeps its permissions.
- cc03446: `lore search` takes `--since`/`--until` (dates or ISO 8601 times) and `--said user`, and the MCP `search` tool takes the same as `since`, `until` and `said`. A new `lore coverage` command shows how many sessions are indexed per month and tool. Sessions written to in the last 30 minutes, usually the asking one echoing the query, now rank below older ones. A query word typed with Vietnamese diacritics no longer matches a different accented word (`xây` finds `xay`, not `xảy`). Existing indexes are rebuilt once.
- cc03446: Opt-in semantic search: `lore embed` installs Transformers.js into `~/.agentlore/runtime`, downloads a multilingual model once and embeds every chunk; `lore search` and the MCP `search` tool then fuse keyword and semantic matches (hits found only by meaning say `by meaning`), and `lore index` embeds new chunks. `lore embed --remove` turns it off, `--no-semantic` skips it for one search. Without `lore embed`, nothing changes and nothing is downloaded. Existing indexes are rebuilt once.
